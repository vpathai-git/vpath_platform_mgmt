# Plain Summary — the CTO briefing

A `/plain-summary` is a fact-based briefing for an educated decision-maker (the CTO),
not a layperson explainer. It's the same idea as the on-demand briefing in the global
CLAUDE.md: one register, self-contained, fast to read.

## When to use

- When the user asks for a summary, status, briefing, "where are we", or "explain it plainly".
- When the user explicitly invokes `/plain-summary`.
- When a debrief will be forwarded (boss/peers) — write it in German if requested.

Do NOT use for a single direct question — answer that directly.

## Structure — pyramid, status first

1. **Status line:** one of **Task beendet / Brauche Feedback / Teilumfang abgeschlossen**
   (or the English equivalent), plus one sentence of context — the task, and any side-quest.
2. **What was achieved and what it implies** — the substance, briefly.
3. **Recommendations as pickable options** — close with critical, reasoned
   recommendations laid out as separated A/B/C choices the reader can pick, not a single
   prescription.

## Register

- Educated CTO / decision-maker, fact-based. Keep domain terms; don't dumb the content down.
- Self-contained: name things in words, never by index/subtask number or bare acronym;
  define any unavoidable term inline.
- Short. No lengthy explanations. Concrete over abstract.
- Language follows the request — German when the user will forward it.
