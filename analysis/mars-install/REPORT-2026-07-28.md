**Four blockers, in order. Three were documented pre-existing gaps; the fourth is
new and structural. None was worked around; each was fixed as a box
precondition, never in the pipeline, and the server checkout was never touched.**

1. **nodesource 403** (reported above). node v22.23.1 installed from the official
   nodejs.org channel, SHASUMS256-verified. v22.23.1 is both the current 22.x LTS
   and venus10's exact version, so parity and freshness coincided. The short-circuit
   condition (`provision-build-host-nuc.sh:188`) is evaluated in a *loopback SSH*
   PATH, because `run_build_vm` is `vm::ssh_nuc` (`lib/vm.sh:694-696`) — so it was
   verified in that context, not in a login shell.
2. **Wrong Gradle cwd** → `setupRegistry` died on a CWD-relative cert copy
   (`setup-registry.sh:92,101`) for a file `generateCerts` writes into `/workspace`.
   This is venus10's recorded **DECISION D1**. Fixed by `MARS12_CHECKOUT=/workspace`
   (the mercury8 pattern) — a register value, not code. Root cause one level down:
   `docs/INSTANCES.md:64` presses "delivery target" and "Gradle cwd" into one field;
   on a from-within NUC they are different things.
3. **The pipeline's own venv could not carry its own gate** → `trainOracle` RED,
   pytest **rc=2** (a *collection* error): `ModuleNotFoundError: No module named
   'jmespath'`. Two distinct venvs exist on the box; the pipeline builds
   `/workspace/.venv` from the ROOT requirements only, while
   `train-oracle.sh:184-194` runs `test_infra/extra` contracts that need
   `jmespath`, declared only in `test_infra/requirements.txt:39`. venus10's **FIX
   #2** verbatim. Fixed with one `pip install -r test_infra/requirements.txt` into
   that venv; verified as a requirement SET (20→51 packages, `--dry-run` satisfied,
   `pip check` clean, gate command `29 passed`) — not by sampling imports.
4. **NEW — sync exclude vs. vendor freeze** → `:buildWorkflowBase` died on
   fork-provenance (`declared 8f6f8622… / actual 468130c1…`). The gate was right:
   exactly two **tracked** files were absent from `/workspace`
   (`…/processors/{generic_json_etl,polarion_publisher}/.claude/settings.local.json`),
   present in the delivered checkout, dropped by `FULL_TREE_SYNC_EXCLUDES`
   (`lib/vm.sh:2638`). Restored exactly those two, byte-identical; the freeze then
   verified **read-only before** re-running (`content verified over 962 files
   (8f6f8622db96…)`, rc=0). `fork-provenance.sh --write` — which the error message
   itself suggests — was refused: it would rewrite the label to match a mutilated
   tree, i.e. launder the gate.

**Open lanes handed to the server stream (filed, not fixed):** (a) the root — a
`.claude/settings.local.json` is tracked inside the vendored `vpath_workflows`

freeze hashes, so on a from-within NUC both cannot hold; (c) **the gate that
